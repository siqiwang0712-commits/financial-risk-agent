# v0.3.2 — Reproducibility & Runtime Integrity

Draft release notes. No v0.3.2 tag or GitHub Release has been created.

v0.3.1 froze and exercised the initial empirical methodology. This release hardens replay semantics, PostgreSQL runtime selection, durable credentials,
tenant/API trust boundaries, provenance completeness, benchmark abstention semantics,
fusion reason codes, versioned narrative-consistency policy, frontend deployability and
container defaults. It adds prospective schema and standalone-period FCF methodology
versions without changing historical v0.3.1 experiments.

The Python 3.11/3.12 matrix uses a complete pinned constraints set, fixed pip and
setuptools versions, and immutable GitHub Actions revisions. Container runtime families
remain versioned but are not claimed byte-identical because base-image digests have not
been independently verified in this environment.

E1/E2/E3 and `research/results/public_v1` remain byte-for-byte unchanged. Their results
are historical frozen evidence and are not regenerated by current code. Predictive
superiority and probability calibration remain not established.

Final closeout validation collects 150 Python tests. In isolated local environments,
149 pass and the single PostgreSQL-dependent test is explicitly skipped on both Python
3.11.9 and 3.12.10, with 90.55% line coverage; PostgreSQL 17 migration/restart
persistence passed in the preceding runtime acceptance run and remains mandatory in CI.
The backend container now installs the locked PostgreSQL runtime, and the production
overlay uses an explicit migration prerequisite with auto-migration and bootstrap
disabled. CI additionally performs an end-to-end PostgreSQL → API readiness smoke test.

PDF resource limits are environment-configured and synchronous parsing work runs in a
bounded worker pool with fail-closed tests for size, pages, text, encryption, invalid
input, timeout and temporary-file cleanup. The frontend lock uses the official npm
registry; both production-only and full dependency audits reported zero current
advisories after a compatible Next.js 15/PostCSS update. This is a point-in-time audit
result, not a claim of permanent vulnerability absence.

The production-overlay container smoke also passed locally on Docker Desktop 29.7.2:
PostgreSQL 17 became healthy, the explicit migration service exited successfully,
`/health/ready` selected and probed `PostgresEnterpriseRepository`, the API ran as a
non-root user, and a dedicated record survived an API-container restart. Production
deployment remains unvalidated.

The stricter validator exposed 24 historical corpus observations where the v1 `total_debt` derivation used one available component while the other was missing. Those frozen observations and E3 results remain untouched. A non-mutating provenance-v2 compatibility view marks the unsupported values `UNAVAILABLE`, records every action and passes the prospective 90-observation integrity gate with zero company overlap and zero future leakage. New ingestion leaves debt unavailable unless both components exist.
